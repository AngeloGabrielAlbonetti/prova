Aula 1 — 29/07

O que é um sistema operacional

  • O SO é o intermédio entre o usuário e o hardware.
  • O SO organiza a execução dos processos: os processos querem usar recursos de hardware, e é o SO que regula a sequência de processos que serão realizados pelo processador.
  • O SO gerencia a memória RAM.
  • Principais conceitos que serão vistos ao longo do curso: processo e memória.

Funcionamento do processador

  • O processador trabalha um processo por vez, e não todos ao mesmo tempo — a troca é tão rápida (cerca de 0,00000001s) que parece simultâneo.
  • O sistema operacional escolhe qual processo será executado logo após a conclusão do anterior.
  • Os processos podem se comunicar entre si e com o SO.
  • Se o SO não reconhece um hardware, ele "pede ajuda" ao driver.

Hierarquia de memória

registrador/registradora (volátil) <---- cache (volátil) <---- RAM (volátil) <---- SSD <---- HD <---- mídias ópticas <---- fita
  • Quanto mais alto na hierarquia: mais rápido, mais caro e menor capacidade.
  • Memórias mais rápidas possuem menor capacidade — é assim que a organização da memória funciona.

Aula 2

Tipos de memória RAM

  • Existem duas memórias RAM: DRAM (dinâmica) — a que conhecemos normalmente — e SRAM, formada por flip-flops (usada na cache).

Componentes do processador

  • Registradores
  • Unidade de controle
  • Unidade lógica e aritmética (ULA)
  • Barramento interno

O SO como camada de software

  • O sistema operacional é a primeira camada de software que gerencia todos os processos.
  • Interface em alto nível → fácil para o usuário entender.
  • Hardware em baixo nível → funcionamento mais interno do computador.
  • O SO fica no meio, intermediando os dois níveis.
  • Os componentes do computador realizam troca de informação constante, que se converte de forma muito mais simplificada para o usuário — esse é o conceito de máquina estendida, uma das definições de sistema operacional.

SO gerenciando recursos

  • Cada processo é utilizado por uma determinada quantidade de tempo (0,0000000001s) pelo SO e depois "roda a vez" para o próximo.
  • Thread: analogia de "vou usar o recurso, mas vou encher duas garrafinhas ao mesmo tempo".
  • Por que o computador trava? Porque não conseguiu terminar a tarefa dentro do tempo — ela continuará quando chegar sua vez novamente na fila.
  • Multiplexação: vários programas podem ser executados ao mesmo tempo. O SO gerencia e protege a memória, dispositivos de entrada/saída e outros recursos, e inclui multiplexação de duas formas: no tempo e no espaço.

Complementos de hardware

  • Flip-flop é uma memória RAM do tipo SRAM; um conjunto de flip-flops forma a memória cache.
  • A memória RAM é formada por capacitores.
  • Principais componentes do computador: processador (CPU/UCP), memória, dispositivos de entrada e saída, barramento.
  • Cada núcleo contém sua própria memória L1 e L2; a L3 é separada do processador.
  • O SO gerencia todo o hardware do computador; se não reconhecer algum componente, recorre ao driver.
  • O SO é, essencialmente, um gerenciador de recursos.

Bug do milênio

  • Acreditava-se que, ao virar de 1999 para 2000, os sistemas "bugariam" e voltariam para 1900, fazendo contas bancárias apresentarem erro (saldo positivo indevido em contas negativas, e vice-versa).
  • Em 1970, os engenheiros usaram apenas 2 bits para representar o ano e depois precisaram trocar para 4 bits — a troca foi motivada pelo alto custo da memória na época.
  • Em 2038 haverá um problema semelhante, mas como a memória é mais barata hoje, a correção será mais fácil.

Dispositivos de entrada/saída

  • Quando um dispositivo de entrada/saída é inserido no computador: ele entra no processo, "sai" e não retorna até completar a operação de E/S; enquanto isso, outros processos continuam sendo executados normalmente; ao concluir, volta à fila normal de processos.
  • Se outro dispositivo de E/S entrar no sistema, ele forma uma fila para concluir sua operação, tudo isso enquanto os processos seguem sendo executados.

Aula 3

Processos e threads

  • a, b, c representam processos; cada um realiza tarefas em seu respectivo período de tempo (ex.: a de 100–200, b de 200–300, c de 300–400 — usando 1 minuto para cada, só para facilitar a explicação).
  • Se um processo não finalizou a tarefa, o sistema sabe onde parou e continuará quando o processo retornar à execução.
  • Analogia: processo = "estou fazendo um bolo"; se o filho é picado por uma abelha, cuido do filho e depois volto para a tarefa, continuando de onde parei.
  • Existem tarefas com mais prioridade que outras → conceito de escalonamento (troca de processos).

Ray casting

  • Técnica de noção de profundidade que altera a altura de paredes/blocos em um mapa 2D conforme a visão do personagem — usada por não haver processamento suficiente na época.
  • A mudança de prioridade no gerenciador de arquivos não causa diferença perceptível em jogos online, pois é algo muito rápido.

O que causa a criação de um processo

  • Inicialização do sistema.
  • Execução de uma chamada de sistema de criação de processo.

Hierarquia e estados de processo

  • Ao finalizar a árvore de tarefas, todos os processos abertos por um processo "pai" são finalizados junto com ele.
  • Estados possíveis de um processo:
  • Em execução (ex.: Word)
  • Pronto (ex.: PowerPoint, Excel)
  • Bloqueado (aguardando entrada e saída)
  • Quando o Word fica pronto, o sistema pega algum processo que está no estado "pronto" para colocar em execução.
  • No simulador de sistema operacional, ao dar prioridade a um processo, somente ele será executado — no sistema operacional real isso não acontece.
  • Exemplo de bloqueio: o Word está salvando um arquivo no HD → o Word fica bloqueado enquanto ocorre o salvamento (operação de E/S); o sistema executa os outros processos na RAM enquanto isso e, ao terminar, o Word volta para o estado "pronto". Outro exemplo: scanf em C — enquanto o usuário não digita, o processo fica bloqueado (operação de E/S).
  • Se dois processos de entrada/saída forem realizados ao mesmo tempo (ex.: instalação), o segundo processo entra em fila atrás do primeiro.

Transições entre estados (setas): 1. Bloqueia o processo de entrada e saída. 2. Retira o processo do "bloqueado" quando finalizado e o leva para "pronto". 3. Traz o processo de "execução" para "pronto". 4. Tira o processo do "pronto" e leva para "em execução". - Teoricamente poderia haver mais duas setas, mas não ocorrem na prática hoje em dia: - "Bloqueado" para "execução" — só faria sentido se houvesse um único processo (o computador gastaria processamento à toa enquanto bloqueado). - "Pronto" para "bloqueado" — não pode acontecer. - Processo de maior prioridade: exemplo "a reitora apareceu na porta".

Eventos que terminam um processo

  • Saída normal (voluntário)
  • Saída por erro (voluntário, dá para resolver)
  • Erro fatal (involuntário) — ex.: divisão por zero

  • Cancelamento por outro processo (involuntário) — outro processo cancela

  • Os processos não sabem em qual posição de memória estão armazenados — quem gerencia isso é o SO, para otimizar o uso da memória.

  • O HD lê os dados um por um (sequencialmente); já na RAM, o tempo de acesso é igual independentemente da posição do dado.
  • Um cheat funciona invadindo o espaço de memória de outro processo (burlando o espaço do SO e alterando alguma informação) — o que normalmente não deveria ocorrer.

Decisão de escalonamento

  • O sistema operacional precisa decidir qual será o próximo processo a executar (comportamento de escalonamento de processo) — anotação incompleta na fonte original.

Aula 4

Organização do gerenciamento de processos

  • O gerenciamento de processos do SO é feito pelo escalonador.
  • Campos do SO: gerenciamento de processos, gerenciamento de memória, gerenciamento de arquivos.
  • Processos têm índice e número de porta.
  • Os processos não sabem em qual intervalo da RAM estão armazenados, apenas quanto de espaço têm disponível — os próprios processos fazem uma requisição de quanta memória precisam.

Troca de mensagens entre processos

-> comunicação
send(destination, &message)
receive(source, &message)
  • Funciona de forma parecida com o TCP: se a mensagem não chegar a tempo, dá timeout e é enviada novamente.
  • Se a confirmação (ACK) se perder, o destinatário deve detectar a duplicata e descartá-la.

Objetivos dos algoritmos de escalonamento

Todos os sistemas - Justiça — o SO deve dar a todos os processos a chance de utilizar o recurso. - Equilíbrio — sempre deve haver algum processo em execução, mantendo uma porção do sistema ocupada. - Aplicação da política — verificar se a política estabelecida está sendo cumprida.

Sistemas em lote - Vazão (throughput) — maximizar o número de tarefas realizadas por hora (unidade de tempo). - Tempo de retorno (médio) — deve ser minimizado, entre a submissão e o término. - Utilização de CPU — manter a CPU sempre ocupada (não pode ficar parada, pois gasta energia à toa). - Descrição: é aquele em que se começa uma tarefa e vai com ela até o final, passando de tarefa em tarefa; a ordem de resolução impacta o resultado — faz-se o processo mais curto (fácil) primeiro, depois os mais longos, para otimizar o tempo total.

Sistemas interativos - Tempo de resposta curto — responder rapidamente às requisições. - Proporcionalidade — satisfazer as expectativas dos usuários. - Cada processo recebe um tempo determinado (ex.: 1 minuto); se não terminar, volta para a fila e recebe mais 1 minuto, até concluir.

Sistemas de tempo real - Cumprimento dos prazos — não pode haver perda de dados. - Previsibilidade — evitar a degradação da qualidade em sistemas multimídia; deve-se saber quando os componentes do sistema vão falhar.

Escalonamento preemptivo x não preemptivo

  • Preemptivo: o SO define o tempo máximo (quantum) que cada processo pode usar o processador; ao terminar o tempo, o SO interrompe o processo e passa para o próximo, retomando depois.
  • Não preemptivo: escolhe um processo para executar e o deixa executar até ser bloqueado (entrada/saída) ou até que ele voluntariamente libere a CPU — pode travar o sistema se o processo ocupar a CPU pelo tempo que quiser.

Aula 5

Categorias de algoritmos de escalonamento

  • Em lote (um processo por vez) — tipos: primeiro a chegar/primeiro a ser servido (FIFO), tarefa mais curta primeiro, prioridades.
  • Interativo (padrão, vai alternando os processos por intervalo de tempo) — round-robin (circular): o processo "gira" por todos os processos; passado o tempo, quando circula de novo, o tempo continua de onde parou. Os valores são contabilizados para a média a partir da conclusão dos processos (quando encontra um zero, contabiliza todo o tempo da média anterior antes do último zero).
  • Em um sistema também existe o tempo de chaveamento entre processos. Em um chaveamento circular, sempre que um processo realiza o último chaveamento entre o processo 0 e o próximo, exclui-se o chaveamento entre ele e o próximo processo.
  • Se o tempo de chaveamento é diminuído, o desempenho do sistema melhora bastante.
  • Existe também o escalonamento por prioridade.

Regra de cálculo (empates)

  • Em caso de empate entre tempo e prioridade, resolve-se pelo FIFO (first in first out).
  • Regra de cálculo da tabela: o valor acumula somando com a linha de cima. Ex.: se A = 4 e B = 5, no FIFO o resultado final é A = 4 e B = 9.

Aula 6

Threads

  • CUDA é a linguagem de programação da NVIDIA voltada para desenvolvimento paralelo.
  • Se o código for sequencial, a quantidade de núcleos interfere na velocidade de leitura/processamento.
  • Thread está associada a um processo, utilizando processamento paralelo: divide-se o processo em vários pedaços para ser executado por diferentes núcleos, sem definir um núcleo específico — é possível dividir um processo em quantas partes quiser.
  • Threads são mais fáceis de criar e destruir do que processos, pois não possuem recursos próprios associados a elas.
  • Por que usar threads? Muitas aplicações realizam múltiplas atividades ao mesmo tempo, e algumas podem ser bloqueadas periodicamente.
  • Exemplo (Word) — 3 threads: uma para interação com o usuário, uma para formatação em segundo plano e uma para salvar o documento em disco.
  • Se fossem 3 processos em vez de threads, cada um teria que invadir o espaço de memória do outro para se comunicar (troca de mensagem), o que é mais lento. Com threads, cada uma funciona sem trocar mensagem com o processo principal — mais rápido.
  • Se uma thread precisar de mais espaço/memória/recurso, ela avisa o processo, e o processo pede ao SO.
  • Threads precisam estar escalonadas para realizar seu processamento.

Condição de corrida (race condition)

  • Exemplo: dois processos (A e B) querem imprimir arquivos.
  • O spool de impressão contém uma fila para os arquivos a serem impressos.
  • As variáveis in e out indicam, respectivamente, os lugares de entrada e saída no spool.
  • Como funciona: o processo quer imprimir um arquivo na RAM → lê o valor de in → coloca o nome do arquivo na posição → ao terminar, incrementa in.
  • Região crítica: ler in; colocar nome; incrementar in.
  • Exclusão mútua: dois processos não podem estar simultaneamente dentro de suas regiões críticas — só um pode acessar por vez; se isso ocorrer, um processo pode ter seus dados sobrescritos.

Condições para evitar condições de corrida (regiões críticas)

  1. Dois processos não podem estar simultaneamente dentro de suas regiões críticas — apenas um por vez.
  2. Nada pode ser afirmado sobre a velocidade ou o número de CPUs.
  3. Nenhum processo em execução fora de sua região crítica pode bloquear outros processos que queiram acessá-la.
  4. Nenhum processo deve esperar eternamente para entrar em sua região crítica.

Algoritmo de Dekker

  • Mencionado apenas pelo nome nas anotações, sem detalhamento adicional.

Recomendação de canal

  • Spanning Tree (anotação isolada na fonte original, sem contexto adicional).

Técnicas de gerenciamento de dados compartilhados

Técnicas: desabilitar interrupções; variáveis do tipo trava; chaveamento obrigatório; solução de Peterson; instrução TSL; XCHG.

  • Desabilitando interrupções: o processo em execução nunca é interrompido, mesmo que tenha acabado seu tempo (ex.: 1 minuto). Pode gerar monopólio do processo, e o processo pode não devolver o controle (travar).
  • Variáveis do tipo trava: variável com valor 0 ou 1; sofre do mesmo problema do spool de impressão; é um nível a mais de controle, mas ainda pode causar monopólio.
  • Chaveamento obrigatório: uma vez de cada — cada processo tem sua vez, mesmo que não precise. Viola a terceira condição (um processo pode estar bloqueando quem precisa, mesmo sem estar na região crítica).
  • Solução de Peterson: evolução do algoritmo de Dekker (uma variável controla por vez); encapsula ações em procedimentos: enterRegion(); e leaveRegion();.
  • Instrução TSL (Test and Set Lock): similar a variáveis do tipo TRAVA, porém em baixo nível; implementação com um único registrador.
  • Instrução XCHG (Exchange): idêntica em propósito ao TSL, porém usa dois registradores.

Problema produtor-consumidor

  • Se o chaveamento ocorrer enquanto um processo está executando, pode chegar um ponto em que ambos os processos "dormem" para sempre.
  • Com semáforos: encapsula-se uma variável na qual se faz um "up" e um "down".
  • Com mutexes: encapsula-se a informação em uma variável na qual se dá "lock" e "unlock".

Monitores

  • Passam a tarefa para o compilador — ele implementa certas soluções por conta própria, para não precisarmos fazer isso manualmente.

Barreiras

  • Travam o acesso até que todos os processos cheguem, para sincronizar o acesso a recursos.

O problema do jantar dos filósofos

  • Filósofo = processo; garfos = recursos compartilhados.
  • Os filósofos precisam dos dois garfos para comer; o processo pede o recurso ao SO.
  • Cenário: se todos tentam pegar o garfo da direita e depois não conseguem pegar o da esquerda → deadlock.

O problema dos leitores e escritores

  • Apenas um escritor por vez pode escrever.
  • Vários leitores podem ler ao mesmo tempo.
  • Enquanto leitores leem, o escritor não escreve; enquanto o escritor escreve, os leitores não leem.
  • O escritor espera pelos leitores que já estavam lendo antes dele chegar, mas não espera pelos leitores que chegaram depois dele.

Aula 7 — Capítulo 6: Deadlocks

  • "Tela azul" está associada à exclusão mútua.
  • Deadlock geralmente está associado a recursos (HD, SSD, memória, etc.) e ocorre tanto em hardware quanto em software.
  • Exemplo: dois processos desejam escanear um documento e gravar em CD — o processo A requisita a impressora e depois o gravador; o processo B requisita o gravador e depois a impressora → deadlock. O mesmo ocorreria se os processos estivessem em rede.

Recursos preemptíveis e não preemptíveis

  • Não preemptível: não pode ser retirado do processo proprietário atual sem causar problema.
  • Preemptível: pode ser retirado do processo proprietário sem prejuízo.
  • Deadlock ocorre com recursos não preemptíveis — gera um impasse.

Definição (do livro)

  • Um conjunto de processos está em situação de impasse (deadlock) se todo processo pertencente ao conjunto estiver esperando por um evento que somente outro processo desse mesmo conjunto poderá fazer acontecer.

Condições para deadlocks de recursos

  1. Exclusão mútua — cada recurso só pode estar alocado a um processo por vez (ou está disponível, ou associado a um único processo).
  2. Posse e espera — processos que já estão usando um recurso podem requisitar novos recursos (recursos compartilhados).
  3. Não preempção — recursos concedidos previamente a um processo não podem ser tomados à força; devem ser explicitamente liberados.
  4. Espera circular — deve existir um encadeamento circular de dois ou mais processos, onde cada um espera por um recurso que está sendo usado por outro do mesmo ciclo.

Modelagem de deadlocks (grafos)

  • Grafos direcionados: bolinha = processo; quadrado = recurso.
  • Seta de processo apontando para recurso = "quero usá-lo"; seta de recurso apontando para processo = "estou sendo usado por esse processo".
  • Quando há um ciclo no grafo = deadlock.

Estratégias para lidar com deadlock

  1. Ignorar o problema — abordagem mencionada no livro; dá trabalho resolver computacionalmente.
  2. Detecção e recuperação — deixa os deadlocks ocorrerem, depois detecta e recupera:
  3. Recuperação por preempção: retira provisoriamente um recurso de um processo e o dá a outro.
  4. Recuperação de retrocesso: gera checkpoints, salvando em arquivos a imagem da memória e os estados dos recursos, sem sobrepor checkpoints anteriores, formando um log de execução.
  5. Recuperação por eliminação de processos: mata o processo — pode causar perda de dados.
  6. Estados seguros e inseguros — o SO identifica estados que podem resultar em deadlock (inseguros) e os que não (seguros).
  7. Ataque às quatro condições:
  8. Exclusão mútua: se um recurso puder estar com dois ou mais processos ao mesmo tempo, não há deadlock — mas ocorre caos com o recurso; existe o processo daemon, cuja única função é requisitar um recurso, emprestando-o para os demais e gerenciando a fila.
  9. Posse e espera: o processo pede de uma vez tudo que vai precisar de recurso — porém nem todo processo sabe o que vai precisar desde o início.
  10. Não preempção: retomar à força um recurso que um processo já está usando (ex.: tirar a impressora de um processo no meio de uma impressão porque ele também precisa de um plotter) é complicado ou impossível na prática; a solução apontada pelo livro (Cap. 6) é a virtualização dos recursos (detalhe que não estava nas anotações de aula).
  11. Espera circular: o processo deve fazer requisições seguindo uma ordem determinada — se um processo pediu a impressora, outro processo só pode pedir o CD se tiver um recurso de nível menor (a impressora) primeiro.

Condição de inanição (starvation)

  • Analogia registrada nas anotações de aula: todo mundo pega o garfo da direita, olha o da esquerda, não está lá, solta, e repete. Não conseguir fazer a tarefa nessas condições não é um deadlock.
  • Atenção: esse exemplo é, na verdade, o problema do jantar dos filósofos (Capítulo 2 do livro, já coberto na Aula 6) — nas anotações de aula ele foi reaproveitado aqui para ilustrar inanição. O Capítulo 6 do livro (Deadlocks) traz um exemplo diferente para "condição de inanição": a alocação de uma impressora entre vários processos. Se o algoritmo sempre prioriza o menor arquivo, e há um fluxo constante de arquivos pequenos chegando, um arquivo grande pode nunca conseguir a impressora — ficando "parado por muito tempo" (inanição). O livro aponta que isso pode ser evitado usando uma política de alocação FIFO.

Aula 9 — Capítulo 4: Sistemas de Arquivos

Conceito

  • Estrutura para organizar o armazenamento de informações a longo prazo.
  • Deve permitir armazenar grandes quantidades de informação.
  • A informação deve sobreviver ao fim do processo que a criou.
  • Múltiplos processos devem ser capazes de acessar a informação simultaneamente.

Requisitos

  • Deve ser possível encontrar um arquivo.
  • Deve ser possível saber se blocos estão livres (HD, SSD).
  • Deve ser possível impedir que um usuário leia dados de outro sem permissão (item confirmado no livro — Cap. 4 — que não estava explícito nas anotações de aula).

Estrutura de arquivos

  • Sequência de bytes.
  • Sequência de registros.
  • Árvore/grafo — em C, é chamado de diretório raiz.

Tipos de arquivo / Operações

  • "Tipos de arquivo" e "Operações" apareciam como tópicos no material, sem anotações registradas na fonte original de aula. O Cap. 4 do livro traz, para "Operações com arquivos", a lista de chamadas de sistema: Create (criar), Delete (apagar), Open (abrir), Close (fechar), Read (ler), Write (escrever), Append (anexar), Seek (procurar), Get/Set Attributes (obter/definir atributos), Rename (renomear).

Sistemas de diretórios hierárquicos

  • Estrutura: diretório raiz → diretório de usuário → subdiretórios de usuário (podem existir vários) → arquivos.

Alocação em disco

  • Setor: menor unidade de informação endereçável — mesmo armazenando uma informação pequena, ela ocupa ao menos um setor; por isso, o tamanho de um arquivo em disco costuma ser maior que seu tamanho real.
  • Alocação contígua: todos os blocos do arquivo devem estar em ordem sequencial no disco.
  • Alocação por lista encadeada: o arquivo é dividido em várias partes espalhadas pelo HD, com a posição de cada uma registrada.
  • Index → I-node (index node): o livro (Cap. 4) confirma que essa é a referência — associa a cada arquivo uma estrutura de dados (I-node) que lista seus atributos e endereços; só precisa estar na memória enquanto o arquivo estiver aberto por um processo.
  • Alocação por lista encadeada usando tabela na memória (FAT): método citado no livro (Cap. 4) que não estava nas anotações de aula — armazena as informações dos arquivos numa tabela na memória (File Allocation Table), usada em SOs mais antigos como o MS-DOS.
  • MBR: esquema do sistema de arquivos que organiza como as partições estão dispostas.

Controle de caminho de arquivos

  • Um diretório/pasta é um arquivo que pode apontar para outras coisas; um arquivo normal não.
  • Permissões rwx — leitura, escrita, execução.
  • Arquivos compartilhados: cada usuário só pode... (anotação incompleta na fonte original).
